# Issue 10: 本周最重要的 8 条 AI 新闻总结

## Summary

为关注 AI 实时动态的读者整理本周最重要的 8 条 AI 新闻。最终产物需要包含 Markdown 新闻简报和对应 PDF 文件，分别放入新建的 `ai-news-md` 与 `ai-news-pdf` 文件夹。

本 issue 来自 GitHub Issue #10，创建时间为 2026-07-24。实现时应以执行当天在 UTC+8 时区对应的自然周为准，并优先选取本周内发生或发布的 AI 领域重要新闻。

## Goals

- 按重要性筛选本周最新、重要、可信的 8 条 AI 新闻，而不是简单按发布时间倒序取前 8 条。
- 面向关注 AI 实时动态的读者，分别用中文和英文总结每条新闻的核心事实、影响和关注点。
- 新建 `ai-news-md` 文件夹，并在其中生成 Markdown 格式新闻简报。
- 新建 `ai-news-pdf` 文件夹，并将 Markdown 简报转换为中文、英文两个版本 PDF 后放入该文件夹。
- 保留新闻来源链接、发布日期或事件日期，便于读者核验。
- 后续提交的 commit message 需要体现 `Assisted-by: AI-SDLC`。

## Non-Goals

- 不生成长期新闻站点、自动订阅系统或爬虫服务。
- 不对新闻进行投资、法律、医疗或政策合规建议。
- 不需要覆盖所有 AI 新闻，只需选取本周最值得关注的 8 条。
- 当前 requirements spec 任务不执行 commit、push、建分支、创建 PR、添加 label 或评论 GitHub；这些 side effects 由 issue gateway 处理。

## User Stories And Acceptance Criteria

### User Stories

- 作为关注 AI 实时动态的读者，我希望快速看到本周最重要的 8 条 AI 新闻，以便了解行业最新进展。
- 作为读者，我希望每条新闻都有来源和日期，方便继续阅读原文或核实信息。
- 作为中文读者，我希望获得中文 PDF 新闻简报，便于快速阅读和分发。
- 作为英文读者，我希望获得英文 PDF 新闻简报，便于在英文环境中阅读和分发。
- 作为仓库维护者，我希望新闻简报同时提供 Markdown 与 PDF，便于在仓库中查看和分发。

### Acceptance Criteria

- 仓库中存在 `ai-news-md` 文件夹。
- 仓库中存在 `ai-news-pdf` 文件夹。
- `ai-news-md` 中至少包含中文与英文两个 `.md` 新闻简报文件，或一个清晰区分中文与英文两个版本的 `.md` 新闻简报文件。
- `ai-news-pdf` 中至少包含中文与英文两个 `.pdf` 新闻简报文件。
- Markdown 简报包含标题、生成日期、本周时间范围、版本语言、8 条新闻条目和来源列表或逐条来源链接。
- 本周时间范围必须按 UTC+8 时区计算，为执行日期所在自然周的周一 00:00:00 至周日 23:59:59。
- 8 条新闻必须从本周候选新闻中按重要性选取；重要性可综合考虑行业影响、技术突破性、政策或市场影响、来源权威性和持续关注价值。
- 新闻条目应按重要性从高到低排序；若两条重要性相近，可再按发布时间倒序排列。
- 每条新闻包含：
  - 新闻标题；
  - 发布日期或事件日期；
  - 来源名称与链接；
  - 对应版本语言的 2 到 4 句摘要；
  - 对 AI 关注者的简短影响分析。
- 新闻条目必须为本周内最新内容；若来源发布时间与事件发生时间不同，应在文中明确说明。
- PDF 内容应与对应语言的 Markdown 主体一致，排版可读，无明显乱码、截断或空白页。
- PDF 不要求特定版式、封面或固定文件命名规范；文件名只需能清晰区分中文和英文版本。
- 后续提交信息中应包含 `Assisted-by: AI-SDLC`。

## Implementation Notes

- 由于新闻具有时效性，实现时必须联网核验最新来源，不能仅依赖模型记忆。
- 可引用英文或中文来源；来源选择应优先考虑权威性、时效性和可核验性，而不是来源语言。
- 优先使用权威或一手来源，例如公司官方博客、研究机构公告、监管机构公告、主流科技媒体、论文或模型发布页。
- 按执行日期在 UTC+8 时区确定本周范围。Issue 创建日期仅用于追溯需求来源，不作为周范围计算基准。
- Markdown 和 PDF 文件名不强制固定格式；建议使用能体现日期和语言的命名，例如 `ai-news-zh-YYYY-MM-DD.md`、`ai-news-en-YYYY-MM-DD.md`、`ai-news-zh-YYYY-MM-DD.pdf`、`ai-news-en-YYYY-MM-DD.pdf`。
- 中文和英文 Markdown 建议结构：
  - 标题与生成日期；
  - 本周时间范围和时区；
  - 按重要性排序的 8 条编号新闻；
  - 总结或趋势观察；
  - 来源链接。
- PDF 转换可使用仓库现有工具、Pandoc、Markdown 渲染库，或其他稳定的本地转换方式；需确保中文字体渲染正常。
- 如果无法安装额外依赖，应优先使用当前环境已有工具完成转换，并在最终说明中记录限制。
- 执行 GitHub side effects 时应遵守 gateway 约束；本 spec 创建任务本身不得 commit、push、建分支或创建 PR。

## Resolved Decisions

- “前 8 条”按重要性筛选和排序，不按发布时间倒序直接截取。
- “这周”按 UTC+8 时区计算执行日期所在自然周。
- PDF 不需要特定版式、封面或固定文件命名规范。
- 需要中文和英文两个版本的 PDF；来源可为英文或中文，但摘要和影响分析必须匹配对应版本语言。

## Validation Plan

- 检查 `ai-news-md` 与 `ai-news-pdf` 两个目录存在。
- 检查 Markdown 文件存在且中文、英文版本各包含 8 条新闻，不多不少。
- 抽查每条新闻链接可访问，日期属于按 UTC+8 计算的本周，或明确说明事件发生于本周。
- 检查新闻条目按重要性排序，并在内容中能体现重要性选择依据。
- 检查 Markdown 中的中英文内容、标题层级和链接格式正确。
- 打开或渲染两个 PDF，确认页数合理、中文无乱码、英文排版可读、内容无明显缺失。
- 对比中文、英文 Markdown 与各自 PDF，确认 8 条新闻标题和主要摘要一致。
- 运行 `git status --short`，确认只有预期新增或修改文件。
